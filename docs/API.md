## Commerce, accounts & careers (v2 integration)
- Customer auth: `getCustomer()` (`src/lib/auth/customer-server.ts`, server, inside Suspense), `useCustomer()` / `useRequireLogin()` (`src/lib/auth/customer.tsx`). The gate runs the action directly while no login method is live.
- `GET /api/auth/providers` → `{ google, mal, email, any }` — which customer logins work now (client: `useAuthProviders()` / `loadAuthProviders()` in `src/lib/auth/providers.ts`). `any:false` → cart/checkout fall back to WhatsApp ordering (`useWhatsAppCartOrder()` in `src/lib/checkout/whatsapp-fallback.ts`).
- `GET /api/auth/mal/status`, `/api/auth/mal/start?next=`, `/api/auth/mal/callback` — MyAnimeList login/connect (staff accounts refused). `next` always goes through `safeNext()`.
- `POST /api/orders` — login required; server re-prices every line and the voucher, idempotent per order id, rate-limited.
- `POST /api/vouchers/validate` — login required; unknown / paused / not-yours codes all answer 404 `not-found`.
- `POST /api/careers/resume-url` `{ jobId, filename, contentType, size }` — signed upload link, only for an OPEN job. `POST /api/careers/apply` — the only way applications are saved.
- Admin settings forms read rows fresh (`readSettingFresh()` in `src/components/admin/crud/settingsFresh.ts`), never the `'use cache'` copy; `saveSettingValue(key, value, { expectedUpdatedAt })` refuses to overwrite a newer save.
